# 受け入れテスト手順書（全機能の一通り確認）

別の AI / 別の実機で「今までの機能がすべて動くか」を確認するための手順です。
自動テスト（A）と手動確認（B）の 2 部構成です。

---

## A. 自動テスト

### A-1. 実行方法（Windows / MinGW-w64）

```
build.bat            … GUI をビルド
build_test.bat       … 既存テスト（454 項目）をビルド
make acceptance      … 受け入れテストをビルド
run_acceptance.bat   … 両方を実行して結果を表示
```

### A-2. 実行方法（Visual Studio 2022）

```
cmake -S . -B build-msvc -G "Visual Studio 17 2022" -DMS_BUILD_ACCEPTANCE_TESTS=ON
cmake --build build-msvc --config Release
build-msvc\Release\acceptance_test.exe
```

### A-3. 判定

| 出力 | 意味 |
|---|---|
| `結果: PASS 143 / FAIL 0` | 自動確認はすべて正常（期待値） |
| `結果: PASS n / FAIL m` | 失敗した項目が末尾に列挙されます |
| 終了コード 0 | 全 PASS / 1 = 失敗あり |

結果は実行フォルダの `acceptance_result.txt` にも保存されます。

### A-4. 自動テストの内容（143 項目）

| 区分 | 主な確認内容 |
|---|---|
| Utils / FileManager | パス操作・改行正規化・UTF-8/Shift_JIS の往復・文字コード判定 |
| 検索エンジン | 完全一致（件数・行・桁）、類似一致、指定行範囲、関数単位、既存スイッチ近傍、include guard の誤検出除外、コメント判定、置換適用 |
| スイッチ生成 | 方式 A〜D のマーカー、テンプレート検証と展開、自動インデント |
| インデント整形 | 共通インデント除去、基準インデント付与、IF ネストの相対保持 |
| プレビュー / 差分 | 置換後テキスト、抜粋、左右 / 上下 / 単純表示、行差分 |
| レポート | HTML / Markdown / JSON 生成と内容、**ファイル単位レポート HTML の表・差分** |
| 検証 / バックアップ / Undo | スイッチ名・予約語・空入力、バックアップ作成と内容一致、単一 / 複数世代 Undo |
| フォルダ走査 / 設定 | 拡張子フィルタ、サブフォルダ、INI 往復（ログ・レポート単位・負荷試験トグル・WinMerge パス） |
| ログ出力 | 3 マクロ、実行時 ON/OFF、環境変数、**種別の予備定義（コンパイルエラー再発防止）**、ASCII のみ、`.c` / `.cpp` 切替 |
| 履歴（undobak） | 記録・`undobak\runs` 配置・一覧・変更前/変更後のスナップショット・差分・ラベル |
| GoogleTest | シグネチャ解析（通常 / void / 可変長 / 参照）、対象関数の重複除去、プロジェクト生成、`MS_LOAD_ITERATIONS`、`MS_SWITCH_ON` |
| 仕様書 / AI | プロンプト内容、Markdown→HTML、エスケープ、サニタイズ、JSON エスケープ、エンドポイント解決 |
| E2E | 検索 → スイッチ生成 → インデント → バックアップ → 書き込み → 履歴 → Undo で完全復元 |

### A-5. 既知の前提

- `acc_tmp` フォルダを実行フォルダに作ります（テスト後に削除して構いません）。
- GoogleTest の**実ビルド・実行は自動テスト対象外**です（CMake と GoogleTest が必要なため）。手動確認 B-9 で行います。
- AI API の**実通信は行いません**（プロンプト生成・JSON 処理のみ）。

## B. 手動確認チェックリスト（GUI）

| # | 手順 | 期待結果 |
|---|---|---|
| B-1 | 起動直後、カーソルを動かさずに画面を見る | 基本設定タブが最初から表示される（白いままにならない） |
| B-2 | 基本設定タブ | 左＝置換方式 / オプション / ヒット時の動作、右＝ログ・レポート・テスト / AI 連携 の 2 カラム |
| B-3 | 基本設定の各コンボ | クリック前に文字が見えている |
| B-4 | タブを 12 枚すべて切り替える | 各タブが即座に描画される。プレビューの比較範囲がボタンと重ならない |
| B-5 | 追加コードタブで「追加コードモード」ON → 3 欄入力 → 「追加位置を検索」 | ヒット件数が出て、プレビュー / ドライラン / 実行が有効になる |
| B-6 | 追加コードの「直後のコード」を空白・改行違いで入力 | それでもヒットする（旧/新コードと同じ条件） |
| B-7 | 新コードに IF 文などを 2 段ネストで入力してプレビュー | 一致行のインデントに合い、内側はさらに 4 スペース下がる |
| B-8 | 基本設定「ログ実装の拡張子」を `.cpp` → 「ログ定義を出力」 | `ms_migration_log.cpp` が生成される（コメント化けなし） |
| B-9 | 「テスト生成」→「テスト実行」 | `tests\gtest` に生成され、CMake があればビルド・実行して結果が出る。`CMakeLists.txt` に `MS_SWITCH_ON` がある |
| B-10 | 基本設定「負荷試験を行う」を OFF → テスト生成 | 生成コードが `MS_LOAD_ITERATIONS=0` 相当となり Load テストはスキップ |
| B-11 | 2 回以上実行 → 基本設定「テスト対象範囲」で 1 回目～2 回目を選択 → テスト生成 | 2 回目で変更した関数だけが対象になる |
| B-12 | 実行 → 履歴タブ | 実行が 1 件増え、ファイル一覧に変更前 / 変更後が出る。`<対象>\undobak\runs\` が生成される |
| B-13 | 履歴タブで 1 ファイル選択 →「この変更だけ元に戻す」 | そのファイルだけ戻り、他の変更は残る（退避は `undobak\sidecars`） |
| B-14 | プレビューの比較範囲を「1 回目～5 回目」にして「HTMLレポートを開く」 | 指定範囲のレポートが生成される（無ければ新規作成） |
| B-15 | システム情報タブの変更範囲を指定 → 仕様書生成 | プロンプト / 仕様書がその範囲の差分を使う |
| B-16 | レポート単位を「ファイル単位」で実行 → `reports\*_file_*.html` を開く | 表・差分が崩れずに表示される |
| B-17 | スイッチ定義ヘッダを生成 → 有効化 / 無効化 | `migration_switch.h` の `#define` が切り替わる |
| B-18 | WinMerge 連携（プレビュー / 履歴） | 比較ウィンドウが開く（1 組 1 ウィンドウ、上限 10） |
